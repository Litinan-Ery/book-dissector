# 图书拆解器 10 本真实图书压力测试用例

## 1. 目标与范围

使用 ego lite 从 `/Users/hna/Downloads/书/` 在真实页面中一次选择 10 本书，验证：

1. EPUB、PDF 和 Markdown 批量导入与异步文本提取。
2. 10 本书进入持久化队列后的顺序、状态、进度和失败隔离。
3. 真实 DeepSeek V4 Flash 的估算、拆解、检查点、取消/恢复、重启恢复和缓存复用。
4. 每本书均生成可读的精华 Markdown，并完成 MyDatabase 同步。
5. 真实质量验收：结构、压缩比、例子具体性、内容告警、随机 5 个观点的原文可追溯性。

本次不读取或记录 API Key，不在测试日志中输出原书正文。

## 3. 测试用例

### ST-01 批量选择与导入

- 前置：当前 checkout 的本地服务健康，`/health` 版本为 `0.2.0`。
- 步骤：在 ego lite 中打开 `http://127.0.0.1:8000`；在文件选择器中一次选中上述 10 个文件；点击“上传书籍”。
- 验收：10 个上传请求全部成功；页面持续轮询；每本的状态最终为“已提取”；书名、格式和字数与提取产物一致。

### ST-02 估算真实性

- 步骤：对每本书打开“一键拆解”，记录调用次数、token、时间和费用区间；与真实任务的 API 调用数及耗时比较。
- 验收：页面四类估算均可见；调用量必须按真实处理单元计算；真实值落在区间内，或差异有被记录且可解释。

### ST-03 10 本持久化队列

- 步骤：依次为 10 本书选择对应类型和“标准”强度，从真实页面发起任务；刷新页面。
- 验收：恰好新建 10 个任务；同一时间最多 1 个 `running`；其余为 `pending`；队列顺序和任务 ID 刷新后不变。

### ST-04 取消与恢复

- 步骤：第 1 本完成至少 1 个模型单元后点击“取消”；等待进入 `cancelled`；点击“继续”。
- 验收：已完成的单元保留；恢复后缓存命中数增加；不再请求已完成单元；任务最终完成。

### ST-05 服务重启恢复

- 步骤：第 2 本运行且至少 1 个单元完成后，停止当前项目所属的 uvicorn 进程；从同一 checkout 重启；用 ego lite 重新打开页面。
- 验收：原 `running` 任务恢复为 `pending/running`；队列顺序不变；已完成单元不重复调用；后续书籍继续执行。

### ST-06 单书失败隔离与失败单元重试

- 步骤：任一单书出现网络、限流、空响应、截断或解析错误时，记录类别；点击“仅重试失败单元”。
- 验收：失败任务为 `error`，错误信息可理解；后续书籍不受影响；重试不覆盖已成功单元；最终该书完成。

### ST-07 约 300 页单书性能

- 对象：290 页文字型 PDF。
- 步骤：记录从该书进入 `running` 到 `done` 的墙钟时间、API 调用数、缓存命中和错误。
- 验收：不含排队时间的耗时不超过 5 分钟；任务完成且中间产物、导出文件存在。

### ST-08 最终产物与质量审计

- 自动验收：任务 `done`；运行中无单元错误；中间 JSON/Markdown 可读；导出 MD 含书名、作者、格式、日期、强度、保留比例和 API 次数；正文非空；内容告警同时出现在页面和导出。
- 比例验收：标准强度按书籍类型审计；通用书以 15% 为目标，小说可更低，技术书可略高；偏差超过目标的 ±25% 时判为失败。
- 人工质量验收：每本书固定随机种子抽查 5 个输出观点；在对应原文章节中核对主体、因果、数字、否定和例子；50/50 均可追溯且无事实冲突才通过。
- 结构验收：输出保持原书核心章节顺序；通用书的观点至少带 1 个具体例子；小说保留人物、主线、转折和结局；技术书保留定义、步骤、关键参数/公式与注意事项。
- 同步验收：MyDatabase hook 返回成功；重复导出是幂等更新，不重复新建书籍条目。

## 4. 通过准则

- 10/10 书籍提取成功、10/10 拆解最终完成、10/10 导出和同步成功。
- ST-01 至 ST-08 无未关闭的 P0/P1 问题。
- 不通过删除失败样本、降低质量阈值、禁用告警或跳过真实模型来“提高通过率”。
- 修复后必须重跑对应回归测试、全量代码测试和 10 本真书压力样本。
